# Architecture Review
Generated: 2026-08-06T20:05:26.209Z
Score: 60/100

## Summary
The codebase follows a reasonably clear pages/components/lib split with well-documented 'pre-built, do not reimplement' UI primitives, but it suffers from a real circular dependency in the storage/meta/context layer, two cases of duplicate-name type/function collisions that will confuse consumers, and heavy copy-paste of the haptic-feedback guard across nearly every page. A spec-only contract.ts file appears to be dead/aspirational and partially conflicts with the real types.ts definitions. Overall the architecture is sound but needs a cleanup pass on shared utilities and import conventions.

## Issues
### Critical
- [circular_dep] src/lib/storage.ts imports reportQuotaExceeded from HolidayContext.tsx, which imports getMeta/setMeta from meta.ts, which in turn imports get/set from storage.ts — a 3-file circular dependency (storage → HolidayContext → meta → storage). — Files: src/lib/storage.ts, src/lib/HolidayContext.tsx, src/lib/meta.ts / Fix: Break the cycle by moving the quota-exceeded event to a standalone event bus/module (e.g. src/lib/quotaEvents.ts) that both storage.ts and HolidayContext.tsx depend on, instead of storage depending on the context module directly.
- [duplication] getMeta()/setMeta() are implemented twice with diverging default logic: src/lib/meta.ts computes the default holiday via getDefaultHolidayId() (nearest upcoming holiday), while src/lib/storage.ts's defaultMeta() always falls back to HOLIDAYS[0]. Both read/write the same STORAGE_KEYS.meta key, so which default 'wins' depends on which module a caller imports from. — Files: src/lib/meta.ts, src/lib/storage.ts / Fix: Keep a single source of truth for meta get/set (e.g. in meta.ts only, built on storage.ts's low-level get/set), delete the duplicate defaultMeta/getMeta/setMeta from storage.ts, and have all callers import from meta.ts.

### Warnings
- [consistency] Two unrelated types share the name ApiError: src/lib/api.ts exports a class `ApiError extends Error`, while src/lib/types.ts exports an interface `ApiError { error: string }`. Similarly RouteState is defined twice with incompatible shapes: contract.ts as a string union ('home'|'script'|...) and types.ts as an object with optional page-data fields (the one actually used by pages like Paywall.tsx). — Files: src/lib/api.ts, src/lib/types.ts, src/lib/contract.ts / Fix: Rename one of each colliding pair (e.g. ApiErrorResponse for the interface, keep ApiError as the class) and delete/rename the contract.ts RouteState since it's superseded by the real implementation in types.ts.
- [duplication] The generateHapticFeedback try/catch wrapper (fireHaptic) is re-implemented nearly identically in 7 places, with Home.tsx even renaming it to safeHaptic and hardcoding a single haptic type instead of parameterizing. — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/pages/Budget.tsx, src/pages/Schedule.tsx, src/pages/Script.tsx, src/pages/Stress.tsx, src/pages/Paywall.tsx, src/pages/Home.tsx / Fix: Extract a single `fireHaptic(type)` helper into src/lib/haptics.ts and import it everywhere, removing the seven near-identical inline copies.
- [dead_code] src/lib/contract.ts declares an extensive set of 'contract' types (RouteState, Holiday, ScriptContext, Script, Promotion, User, generateScriptFn, useHolidayFn, usePromotionRewardFn, ROUTES, DEFAULT_USER) but none of them are imported by any page/component/lib file shown — the real implementations (types.ts, api.ts, HolidayContext.tsx, usePromotionReward.ts) use their own independently-defined shapes instead. — Files: src/lib/contract.ts / Fix: Either wire the actual implementations to satisfy/import these contract types (if this file is meant to be a build-time source of truth), or delete it now that all packets have been implemented, to avoid two diverging definitions of the same concepts.

### Suggestions
- [dead_code] storage.ts's getItem/setItem are commented as a compatibility alias for HolidayContext, but HolidayContext.tsx actually imports getMeta/setMeta from meta.ts, not getItem/setItem — these aliases appear to have no real callers. — Files: src/lib/storage.ts / Fix: Grep for real usages of getItem/setItem; if none exist outside this file, remove them.
- [structure] src/components/__DbgProbe.tsx is a console.log debug probe that doesn't appear to be referenced from App.tsx's route list, and its dunder-prefixed naming is otherwise only used for the intentionally dev-only pages/__TdsGallery.tsx (which is gated by import.meta.env.DEV and documented for tree-shaking). __DbgProbe.tsx has no such guard/documentation. — Files: src/components/__DbgProbe.tsx / Fix: Either delete the leftover debug probe, or move it next to __TdsGallery.tsx with the same DEV-only import guard and a comment explaining its purpose/removal criteria.
- [consistency] Import style for shared modules is inconsistent: Budget.tsx, Schedule.tsx, Script.tsx, Stress.tsx, TossPurchase.tsx use the '@/...' path alias, while Home.tsx, Paywall.tsx, HomeBanner.tsx use relative '../lib/...' / './...' imports for the same modules. — Files: src/pages/Home.tsx, src/pages/Paywall.tsx, src/pages/Budget.tsx, src/pages/Schedule.tsx / Fix: Standardize on the '@/' alias across all files (already configured, since most pages use it) and run a repo-wide find/replace for the remaining relative imports.
- [duplication] Amount.tsx and CountUp.tsx duplicate the same nowrap/tabular-nums wrapper span markup and inline style object, differing only in the animation logic. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract the shared `<span style={{display:'inline-block', whiteSpace:'nowrap', fontVariantNumeric:'tabular-nums', ...}}>` wrapper into a small internal NumericText helper that both components render into.
- [naming] constants.ts's HOLIDAYS list (id/label/date) and contract.ts's Holiday type (date/name/isLunar) model the same real-world concept with different field names (label vs name, no isLunar in constants), increasing the chance of confusion when reconciling the two. — Files: src/lib/constants.ts, src/lib/contract.ts / Fix: Consolidate on a single Holiday shape used everywhere, or clearly document that contract.ts's Holiday is a distinct, unimplemented concept if intentional.
