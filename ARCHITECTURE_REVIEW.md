# Architecture Review
Generated: 2026-08-07T20:08:57.882Z
Score: 42/100

## Summary
The routed surface of the app (App.tsx → Home.tsx via ScreenScaffold/Card/SummaryHero) is clean, well-commented, and consistent, but the repository as a whole is in poor shape: the vast majority of page components and several components that only they use are never wired into the router, and a stale parallel type-contract file conflicts with the real data model. Cross-cutting patterns (haptics wrapper, inline numeric styling) are copy-pasted rather than shared, and leftover scratch files sit inside the production pages folder.

## Issues
### Critical
- [dead_code] App.tsx only registers routes for '/' (Home) and the dev-only '/__tds-gallery'. HomePage.tsx, CalendarPage.tsx, BudgetPage.tsx, ScriptPage.tsx, ScriptResultPage.tsx, SetupPage.tsx, MoodNewPage.tsx and ReportPage.tsx (roughly 1,600 lines combined) are never imported by the router, and are the sole consumers of AdSlot, TossPurchase, Sparkline, and TossRewardAd, making those components transitively dead too. FloatingTabBar also has no consumer anywhere in the shown code. — Files: src/App.tsx, src/pages/HomePage.tsx, src/pages/CalendarPage.tsx, src/pages/BudgetPage.tsx, src/pages/ScriptPage.tsx, src/pages/ScriptResultPage.tsx, src/pages/SetupPage.tsx, src/pages/MoodNewPage.tsx, src/pages/ReportPage.tsx, src/components/AdSlot.tsx, src/components/TossPurchase.tsx, src/components/Sparkline.tsx, src/components/TossRewardAd.tsx, src/components/FloatingTabBar.tsx / Fix: Either add these routes to App.tsx (react-router Route entries pointing at each page) or, if they are genuinely superseded by Home.tsx, delete them along with their orphaned child components to shrink the bundle and avoid maintainers editing code that never runs.
- [duplication] src/lib/contract.ts defines a second, conflicting type system for the same entities already modeled in src/lib/types.ts — e.g. contract's MoodEntry/VisitRecord/Budget/Script(title,content,usage) vs. types.ts's MoodLog/Visit/BudgetItem/Script(situation,tone,question,resultText). It also declares function-shape aliases (useAppDataFn, calculateMoodStatsFn, initTossSessionFn, generateScriptFn) that don't match the real useAppData.ts/storage.ts implementations. The file's own comment says it's load-bearing ('추측이 어긋나 병합에서 무너지는 것을 막기 위한 파일') but it has clearly drifted from the actual code. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/useAppData.ts, src/lib/storage.ts / Fix: Delete contract.ts if it's stale scaffold output, or regenerate/sync it from the real types.ts and useAppData.ts so there is a single source of truth for entity and function shapes.

- [structure] Scratch/debug files live inside the production src/pages directory: __chiptest.tsx, __noJsxTest.tsx (completely empty), __tmpMinimal.ts and __tmpMinimal.tsx (same base name, two extensions, both unused). None are imported anywhere. — Files: src/pages/__chiptest.tsx, src/pages/__noJsxTest.tsx, src/pages/__tmpMinimal.ts, src/pages/__tmpMinimal.tsx / Fix: Delete these scratch files, or if they're needed for local experimentation, move them outside src/ (e.g. a gitignored scratch/ dir) so they don't ship with the app or confuse contributors.
- [naming] File naming convention for pages is inconsistent: the only actually-routed page is 'Home.tsx' (no suffix) while every other page uses an 'XxxPage.tsx' suffix. Worse, 'Home.tsx' and 'HomePage.tsx' coexist in the same folder with very similar names but different implementations (JSX vs createElement) and different routing status, which is a strong source of wrong-import mistakes. — Files: src/pages/Home.tsx, src/pages/HomePage.tsx / Fix: Pick one convention (e.g. always 'XxxPage.tsx') and rename Home.tsx to HomePage.tsx (retiring/merging the old HomePage.tsx), or clearly namespace the unused ones (e.g. move to a drafts/ folder) so the active page is unambiguous.

### Suggestions
- [consistency] Two rendering styles are used for pages depending on a test-runtime constraint: Home.tsx and __TdsGallery.tsx use JSX, while every *Page.tsx file uses React.createElement(h, ...) because their tests require(...) the module in Node without JSX transpilation. This doubles the mental model required to write a new page and is easy to violate silently (a new page added with JSX would break its own test loader with no compile-time warning). — Files: src/pages/Home.tsx, src/pages/HomePage.tsx, src/pages/BudgetPage.tsx, src/pages/CalendarPage.tsx, src/components/Card.tsx, src/components/PageShell.tsx, src/components/ScreenScaffold.tsx / Fix: Standardize on one loading strategy for page tests (e.g. run them through the same transpiler as the app, such as via a Vite/esbuild-backed test runner) so all pages can use plain JSX, eliminating the createElement workaround and its duplicated NOTE comments.
- [duplication] Amount.tsx and CountUp.tsx both hardcode the identical wrapper-span style object (display:inline-block, maxWidth:100%, whiteSpace:nowrap, fontVariantNumeric:tabular-nums) used to keep a number+unit from wrapping. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Factor the shared style into a small exported constant (e.g. NUMERIC_NOWRAP_STYLE in lib/utils.ts) and reuse it in both components.
